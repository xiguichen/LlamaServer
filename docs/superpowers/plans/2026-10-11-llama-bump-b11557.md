# llama.cpp Tag Bump (b9553 → b11557) Implementation Plan

> **Historical (2026-10-11).** Completed. Current facts live in `docs/STACK.md`; do not use this plan as reference.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin `vendor/llama.xcframework` to llama.cpp `b11557` to pick up the Metal few-row MMA mat-mul kernels (#29869/#30065, +52% on 2-row batched decode — the upstream-confirmed fix for speculative-verify being slower than serial), the q8_0-KV flash-attention dequant path (#27390), and MTP probabilistic draft sampling (#27694) — then verify on device whether MTP becomes net-positive.

**Architecture:** Single-process iOS app; llama.cpp ships as a prebuilt xcframework fetched by `scripts/fetch-llama-xcframework.sh` and regenerated in CI. The bump is a pin change plus the source adaptations the 4-month API drift requires. No local llama.cpp compilation (AGENTS.md); the compile gate is CI.

**Tech Stack:** Swift (iOS), C++ shim over llama.cpp staging API, XcodeGen project, GitHub Actions CI.

**Spec:** This plan (drift analysis performed 2026-10-11 by diffing `include/llama.h` at b9553 vs b11557 and cross-checking every `llama_*`/`ggml_*` symbol used in `Sources/App/`).

## Drift Analysis (the decisions this plan encodes)

Verified present in b11557 with **identical signatures** (no change needed): all batch APIs (`llama_batch_init/free/get_one`, struct fields `token/embd/pos/n_seq_id/seq_id/logits/n_tokens`), `llama_init_from_model`, `llama_decode`, `llama_get_memory` + all `llama_memory_*`, all `llama_sampler_*` except penalties, `llama_get_logits_ith`, `llama_tokenize`, `llama_token_to_piece`, `llama_vocab_*`, all `llama_model_meta_*`, `llama_model_is_hybrid/is_recurrent/n_swa/n_layer/n_embd/n_head/n_head_kv/n_ctx_train`, `llama_state_seq_load_file/save_file`, `llama_chat_apply_template`, `llama_model_chat_template`, `llama_log_set`, `llama_model_load_from_file`, `LLAMA_CONTEXT_TYPE_MTP`, `llama_vocab_n_tokens`. All `llama_context_params` fields we set (`n_ctx/n_batch/n_ubatch/n_threads/n_threads_batch/swa_full/ctx_type/n_outputs_max/n_rs_seq/ctx_other/flash_attn_type`) still exist. `ggml_metal_buffer_is_shared` (b9553-only) appears in our source **only in comments** — never called.

**Drift items requiring action:**

1. `llama_sampler_init_penalties` gained a leading `int32_t n_vocab` parameter. One call site: `Sources/App/LlamaInference.swift:1141-1143`. Supply `llama_vocab_n_tokens(vocab)` (vocab is already a stored property).
2. The MTP staging API moved from llama.h (b9553) into `src/llama-ext.h` (b11557) with unchanged signatures: `llama_set_embeddings_nextn(ctx,bool,bool)`, `llama_get_embeddings_nextn(ctx)`, `llama_get_embeddings_nextn_ith(ctx,int32_t)`, `llama_get_ctx_other(ctx)`. `Sources/App/LlamaExtShim.cpp` links against their **C++-mangled** names in the shipped dylib; identical signatures ⇒ identical mangling (`__Z26llama_set_embeddings_nextnP13llama_contextbb` etc.), but this MUST be verified with `nm` against the actual b11557 binary before trusting it — that check is a plan step.
3. `llama_model_params`: `use_mmap/use_mlock/use_direct_io` removed, `load_mode/lazy_mode/load_mtp` added. We set only `n_gpu_layers = 999` — **no source change** (new fields get defaults from `llama_model_default_params()`).
4. `llama_context_params` gained `n_outputs_max_per_seq`/`moe_cache_size` — we don't set them; defaults (0) preserve old behavior.

## Review Focus

1. **Shim symbol resolution** — if any of the 4 mangled staging symbols is missing/renamed in the b11557 dylib, the CI *build* job fails at link. Owned by Task 1 (nm step, before push).
2. **MTP quality regression from upstream semantic changes** — #30017/#30257/#27694 touched h_nextn cropping and MTP draft sampling; signatures match but behavior may differ (e.g. acceptance rate drop below the historical 58–64%). Owned by Task 2 (compliance suite + acceptance-rate reading in the A/B).
3. **q8_0 KV + flash attention behavior change** — #27390 replaced the Metal quantized-KV FA path with a dequant-to-F16 route; watch the MTP-off baseline for throughput/RSS regressions vs the historical 18–19 tok/s. Owned by Task 2 (baseline leg of the A/B).
4. **RSS regression** — new defaults (`moe_cache_size`, load-mode changes) could alter footprint on a device with ~3.1 GB headroom; a load failure or MEMORY WARNING at startup is the symptom. Owned by Task 2 (load step, check llamaserver.log).
5. **Batch-decode assertion behavior** — the hybrid MTP verify path decodes token+embd batches; `llama_context::decode`'s assert and output bookkeeping changed upstream (#29622). A crash here shows as a generation abort in the log. Owned by Task 2 (first MTP-on generation).
